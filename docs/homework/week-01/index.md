# 概念回答
1.什么是微服务架构？微服务架构就是把一个大系统按照业务分工拆成一组能各自干活、各自负责，然后互相通过约定合作的小团队。
##
2.微服务和单体架构的主要区别是什么？单体架构是一个团队围着一个大系统转；微服务是把系统按业务拆成多个独立负责、独立运行的小单元。
##
3.为什么本课程先实现单体系统，再逐步拆分为微服务？因为一开始最重要的应该是把业务跑通，而不是把系统拆复杂。单体前期开发快、技术负担小、重构成本低，先做单体能让我们快速验证业务、理解领域，并发现真正的拆分边界，在业务还不确定、团队和规模还不大时，单体应该是更可控的起点。
##
4.为什么作业需要提供可重复运行的测试或验证脚本？因为可重复运行的测试或验证脚本不依赖个人电脑上的绝对路径，重新执行时可以得到相同的结果，方便复核；写成脚本可避免忘记关键步骤，输出的日志方便定位问题，可以重复运行，不产生脏数据。
