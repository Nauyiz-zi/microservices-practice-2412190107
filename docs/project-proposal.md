# 校园二手教材交易平台项目提案

## 1. 项目名称

校园二手教材交易平台（Campus Second-hand Textbook Trading Platform）

项目面向高校学生在学期初和学期末的教材流转需求，提供二手教材发布、检索和交易的基础能力。

## 2. 目标用户

| 用户角色 | 核心诉求 | 本期关注程度 |
|---|---|---|
| 学生买家 | 搜索需要的教材，查看书况和价格，下单购买 | 高 |
| 学生卖家 | 发布闲置教材，管理可售数量，处理订单和发货 | 高 |
| 平台管理员 | 审核教材信息，管理用户，处理异常交易 | 中 |
| 游客 | 浏览教材列表和详情，注册登录后参与交易 | 低 |

本期优先服务学生买家与学生卖家。管理员能力先保留基本治理需求，游客只提供浏览入口。

## 3. 优先实现的业务场景

### 场景名称：单本二手教材在线交易

**场景目标**

让买家能够从搜索教材开始，完成一次单本二手教材的下单、模拟支付、发货和确认收货流程，形成最小可验证交易闭环。

**参与角色**

买家、卖家。

**前置条件**

卖家已经发布至少一本二手教材，教材处于可售状态，并且有可售数量。

**主流程**

1. 卖家发布二手教材，填写教材名称、ISBN、作者、出版社、成色、售价和可售数量。
2. 买家按书名或 ISBN 搜索教材，进入教材详情页查看书况、价格和卖家信息。
3. 买家确认购买并提交订单。
4. 系统检查教材是否可售，并锁定一本教材库存。
5. 买家完成模拟支付。
6. 卖家确认订单并发货。
7. 买家确认收货。
8. 系统将订单标记为已完成，并扣减对应教材库存。

**首期范围约束**

- 一个订单只包含一个卖家的一本教材。
- 一次交易只购买一本教材。
- 支付和物流采用模拟方式。
- 评价、退款、优惠券、多卖家拆单暂不纳入首期范围。

**优先理由**

该场景串联教材发布、检索、库存、订单、模拟支付和履约，是后续拆分教材服务、库存服务和订单服务的最小完整业务闭环。

## 4. 两个核心模型

### 4.1 教材（Textbook）

**模型职责**

记录一本可交易二手教材的基本信息和交易属性，是买家检索和下单的对象。

**关键信息**

- 教材标识：教材 ID
- 图书信息：ISBN、书名、作者、出版社、版次
- 交易信息：成色、售价、可售数量、上架状态
- 归属信息：卖家 ID
- 时间信息：发布时间、更新时间

**状态与约束**

- 教材必须处于上架状态才允许被购买。
- 可售数量不能小于零。
- 已被订单锁定的数量不能再次出售。
- 下架教材不能被新订单购买。

**后续演进**

后续可以将“教材目录信息”和“交易库存信息”拆分到教材目录服务与商品库存服务。

### 4.2 订单（Order）

**模型职责**

记录买家一次购买行为及其状态变化，是交易流程的核心凭证。

**关键信息**

- 订单标识：订单 ID、订单号
- 参与方：买家 ID、卖家 ID
- 交易对象：教材 ID、教材名称、购买数量
- 金额信息：单价、订单金额
- 状态信息：订单状态
- 时间信息：创建时间、支付时间、发货时间、收货时间

**状态流转**

待支付 → 已支付 / 待发货 → 已发货 → 已完成

异常流转：

待支付 → 已取消
待支付 → 超时关闭

**首期约束**

- 一个订单只关联一个卖家和一本教材。
- 订单状态只能按既定顺序流转。
- 订单完成后才扣减对应教材库存。

**后续演进**

后续可以扩展订单明细、多教材订单、多卖家拆单、支付服务、物流服务和评价服务。

## 5. 本阶段不实现的内容

本阶段只完成项目提案和概念规划，不实现以下内容：

- Java 实体类或领域模型代码
- 数据库表、SQL 和数据库迁移脚本
- Repository、Service 和完整 REST API
- 真实支付和真实物流接口
- 消息队列、分布式事务和监控告警

## 6. 与后续微服务拆分的关系

- 教材模型后续可演进为教材目录服务和商品库存服务。
- 订单模型后续可演进为订单服务，并拆出支付和履约能力。
- 用户与认证后续可拆分为独立认证授权服务。
- 通知能力后续可通过订单和支付事件拆分为通知服务。
